Motivation

💥 The "Works on My Machine" Crisis in ML

Why production ML engineers never run models on bare operating systems

Traditional Bare Machine Setup Containerized Environment (Docker)
⚠️ Python Version Drift: Student A has 3.10, Student B has 3.12, leading to syntax and library breakages. ✅ Fixed Python Runtime: Base image locks the exact interpreter (Python 3.11 / 3.12) universally.
⚠️ Dependency Hell: NumPy 2.0 release breaking existing Pandas / Scikit-Learn installations. ✅ Frozen Requirements: Dependencies installed once inside immutable image layers.
⚠️ C-Extension Compilations: Missing Xcode tools on Mac or Visual C++ on Windows crashing pip install. ✅ Pre-Compiled Wheels: Standard Linux Debian/Ubuntu containers with all binary libraries pre-built.
⚠️ Cloud Deployment Friction: Code runs on laptop, fails instantly on AWS / Azure Linux servers. ✅ Build Once, Run Anywhere: Identical execution from local MacBook to cloud cluster.

Mathematical Relationship

We want our machine learning model to discover the linear relationship:

y = w · X + b
  • X (Input): Study Hours
  • y (Output): Exam Score (0 to 100)
  • w (Weight / Slope): Points gained per hour studied
  • b (Bias / Intercept): Base score without studying
Application Logic

🧠 The ML Pipeline: train_and_predict.py

Clean Scikit-Learn code that fits the data, prints metrics, and exports the model

import pandas as pd
from sklearn.linear_model import LinearRegression
import joblib

# 1. Load dataset
df = pd.read_csv("data.csv")
X = df[["study_hours"]].values
y = df["exam_score"].values

# 2. Fit Scikit-Learn Linear Regression model
model = LinearRegression()
model.fit(X, y)

# 3. Print learned parameters & test prediction
print(f"Learned: Score = ({model.coef_[0]:.2f} × Hours) + {model.intercept_:.2f}")
print(f"Predicted for 6 hours: {model.predict([[6.0]])[0]:.1f}")

# 4. Save trained artifact to output directory
joblib.dump(model, "output/model.joblib")
Container Specification

🐳 Authoring the Dockerfile

Translating code, data, and environment into container layers

# 1. Lightweight base image
FROM python:3.11-slim

# 2. Working directory
WORKDIR /app

# 3. Install dependencies
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt

# 4. Copy training data & script
COPY data.csv .
COPY train_and_predict.py .

# 5. Output directory & execution
RUN mkdir -p /app/output
CMD ["python", "train_and_predict.py"]
FROM Base Layer
Pulls minimal official Debian Linux with Python 3.11 pre-installed (~50MB).
COPY & RUN Layer Caching
Copies requirements first so Docker caches installed packages unless requirements change.
CMD Entrypoint
Specifies the default command executed when the container spins up.
Hands-On Practice

🔨 Task 1 & 2: Build & Run Locally

Executing training inside your isolated container

1. Build the Docker Image
docker build -t my-first-ml:v1 .
⚠️ Crucial: Do not omit the trailing dot .! It tells Docker the build context is the current folder.
2. Run the Container
docker run --rm my-first-ml:v1
The --rm flag automatically removes the stopped container process, keeping your system clean.
Persistence

💾 Task 3: Persist Model via Volume Mount

Extracting the trained model.joblib artifact onto your host laptop

The Stateless Container Problem

Containers are ephemeral. Any file saved inside /app/output disappears when the container terminates.

To retain model artifacts, we mount a local laptop directory into the container:

Volume Command
mkdir -p output

docker run --rm \
  -v $(pwd)/output:/app/output \
  my-first-ml:v1
Verify Local File Creation:
ls -la output/
# Look for model.joblib directly on your laptop!
Cloud Registry

☁️ Task 4: Push to Your Docker Hub

Publishing your ML container so anyone or any cloud server can pull it

Step 1: Authenticate
Login to Docker Hub:
docker login
Step 2: Tag
Format: <user>/<repo>:<tag>
docker tag my-first-ml:v1 \
  <YOUR_USER>/my-first-ml:v1
Step 3: Push
Upload image layers:
docker push \
  <YOUR_USER>/my-first-ml:v1
Check your public repository live in browser:
👉 https://hub.docker.com/r/<YOUR_DOCKERHUB_USERNAME>/my-first-ml
